# v4 modernization review

Reviewed on 2026-10-25. Scope: all tracked application source, renderer assets, dependency declarations/lockfile, and automation. This is an engineering review with regression tests, not an independent penetration test.

## Findings addressed

- **Renderer privileges:** Node integration was enabled, context isolation and sandboxing were disabled, and remote JavaScript was loaded. Privileged work now runs in the main process. The isolated sandboxed preload exposes a narrow API; every IPC handler checks the exact window, main frame, and local page URL. The renderer loads only local assets under a restrictive CSP. Navigation, popups, webviews, and permissions are denied.
- **Shell execution:** file opening interpolated paths into OS shell commands. The app now uses `shell.openPath`; external links come from an explicit key-based allowlist. Tool invocations use `spawn` with argument arrays and no shell. Packaged Electron fuses disable Node mode, Node environment options, and CLI inspection, require ASAR loading, and enable supported ASAR integrity checks.
- **Obsolete dependencies:** Electron 25, old Axios, ytdl-core, fluent-ffmpeg, electron-context-menu, and Babel were removed. Electron is 45.0.0; electron-builder is 26.18.0. Code runs directly on the supported Node/Electron runtime. The only direct runtime npm dependency is yauzl 3.4.0 for controlled ZIP entry streaming.
- **Executable installation:** the old first-run downloader used mutable latest URLs, no checksums, and mode 0777. The manifest now pins tool versions and SHA256 values. Downloads have size/time limits, archives write only expected executables, tools use owner-only executable permissions, and installation commits only after all tools verify. Failed or cancelled installations leave no usable partial cache. Cached executable contents are rechecked before use.
- **YouTube support:** switched to yt-dlp 2026.10.21 with Deno 2.9.8 for current JavaScript challenges. Upstream user configuration is ignored; playlists and self-update are disabled. FFmpeg/FFprobe are 9.0.2 stable builds on Linux/macOS and dated builds of the 9.0 branch on Windows. The upstream project can still be affected by YouTube changes or account/network restrictions.
- **Inputs and filenames:** URLs are restricted to recognized YouTube video hosts and canonicalized to a single video ID. Invalid timestamps, reversed/empty ranges, out-of-video bounds, and malformed IPC option types are rejected. Filenames are bounded and sanitized; Windows reserved names and path traversal are handled. Output folders include the unique video ID. A filename cannot overwrite the cached source video.
- **File integrity:** source downloads and conversions write into temporary directories and rename only completed nonempty outputs. Errors preserve previous successful outputs and clean temporary files. Conversion failures now propagate to the UI. MP3 export cuts audio directly.
- **Lifecycle and errors:** a single main-process job prevents competing writes. Cancel aborts network transfers and terminates tool process trees. Child processes have execution/output limits. Closing the window stops its job. Form state is restored after errors; progress uses plain text and is bounded. Patch-version update detection was corrected, and update-check failure no longer blocks the app.
- **UI:** preserved the layout, gradients, labels, icons, and local Roboto font. Added a Cancel button shown only during work, accessible progress logging, keyboard-operable links, accurate checkbox labels, strict time patterns, bounded inputs, and robust pasted-time formatting. Removed automatic focus jumping, which interfered with editing timestamps.
- **Build and releases:** removed obsolete Travis/Babel configuration and shell-specific startup commands. Standardized on Node 24 LTS/npm with a committed lockfile, lint/format/tests, npm audit, and commit-pinned Actions. CI checks Linux/Windows/macOS. Packaging uses native Linux/Windows/macOS runners, tests real tools, validates tags, includes architecture in filenames, and publishes only on an explicit release path to a draft. Broad environment forwarding and the long-lived custom CI token were removed.
- **Maintenance and licenses:** added Dependabot configuration, security reporting guidance, GPL license text, third-party notices, and current setup/release documentation.

## Verification

- `npm run check`: passed ESLint, Prettier, and all **36 regression tests** on Linux x64 with Node 24.22.1.
- `npm audit --audit-level=low`: **0 known vulnerabilities**, including development dependencies. The current electron-builder tree still emits upstream deprecation notices for development-only transitive packages (`glob`, `inflight`, `rimraf`, and `boolean`); those are not runtime app dependencies, and no incompatible major-version overrides were forced into upstream tooling.
- electron-builder configuration: loaded and packaged successfully with electron-builder 26.18.0.
- `git diff --check`: passed.
- Regression coverage includes URL/time/option validation, filename safety, patch update detection, trusted IPC senders, external link restrictions, literal subprocess arguments, failure/timeout/cancellation behavior, checksum enforcement, tool-cache recovery, malicious ZIP entries, transactional outputs, direct MP3 export, and renderer form/error/cancel behavior under JSDOM.
- The Linux x64 media smoke test downloads and verifies the real manifest assets, runs all four executables, generates a synthetic video, exports two-second H.264/AAC and MP3 clips, and uses FFprobe to validate duration and streams. It contacts binary hosts, but does not rely on YouTube availability.
- Live YouTube workflow: retrieved metadata and downloaded the public 19-second video `jNQXAC9IVRw`, cut 00:00:01–00:00:03 to a custom-named MP4, and confirmed H.264/AAC streams and an exact `2.000000`-second duration with FFprobe. Temporary media was removed afterward. The historic yt-dlp fixture `BaW_jenozKc` was unavailable; this did not prevent the accessible-video check from passing. An offline test or one public video does not establish that every YouTube video/network works.
- Linux x64 desktop, under Xvfb because this host has no display session: `scripts/smoke-desktop.js` drove the real Electron renderer, preload, and main process. The development app passed isolation checks (no Node, frozen bridge, local Roboto), rejected a non-YouTube target, a `file:` link, and a reversed range, restored the form after that error, installed tools on first run, saved a custom-named two-second H.264 MP4, reused the download for MP3, forced one redownload, and cancelled back to idle. FFprobe checked the UI-produced clips. A packaged AppImage passed that same network workflow. After the desktop-entry correction below, the rebuilt image passed the isolation, rejection, and form checks. Screenshots are `dist/desktop-development.png` and `dist/desktop-packaged.png`.
- Linux AppImage: `npm run build -- --linux --x64` wrote `dist/yt-dlandcut-3.0.0-linux-x86_64.AppImage` while the package version was still 3.0.0. The published version is 4.0.0 because GitHub already has a v3.0.0 release. The desktop entry is `com.electron.yt-dlandcut.desktop` with `StartupWMClass=com.electron.yt-dlandcut` and `Exec=AppRun %U`. `appImage.executableArgs` is an empty array so electron-builder's legacy AppImage default does not put `--no-sandbox` on every launch. `AppRun` adds that flag only when `unshare -Ur` fails. This host fails that check (`/proc/sys/kernel/apparmor_restrict_unprivileged_userns` is 1, and the Electron `chrome-sandbox` helper is not setuid), so the packaged smoke ran through that fallback and still kept the renderer isolated. Host security settings were not changed. The image could not be FUSE-mounted here because `libfuse.so.2` is absent; it ran with `APPIMAGE_EXTRACT_AND_RUN=1`. Opening the output folder in a desktop file manager was not exercised.

## Remaining launch checks

1. Repeat the desktop and installer checks on clean Windows x64, macOS Intel, and macOS Apple Silicon machines, and on a normal Linux desktop where FUSE and user namespaces work. Confirm the AppImage keeps the Chromium sandbox there, and that opening files and folders uses the desktop environment. Linux x64 behavior above was verified in this workspace only.
2. Verify a public YouTube video you own or have permission to use from each target network. Confirm both video and MP3 outputs, realistic long-video behavior, and expected errors for unavailable/account-restricted videos. A known historic yt-dlp test video was reported unavailable during this review; live service checks must use currently accessible content.
3. Configure macOS Developer ID signing/notarization and Windows code signing for public distribution. Credentials are not present or configured in this checkout. Do not publish unsigned release candidates as if signing and OS trust checks had passed.
4. Exercise the new GitHub Actions workflow in the repository. Source review and local checks do not prove hosted runners, repository release permissions, and signing are configured correctly. Publishing remains a maintainer action on the draft release.
5. Verify platform/OS minimums and upstream binary dependencies on the actual release machines before declaring a support matrix. Linux/Windows ARM64 tool manifests are present, but those installer targets have not been validated as releases.

## Maintenance after release

Keep Electron and the npm tree current, review Dependabot changes, and run `npm audit`. For upstream extraction changes, deliberately update the external-tool manifest, review its diff and upstream release notes, run checks/media tests, smoke-test live downloads, and ship a new application version. Previously cached versioned tools remain on disk for recovery; old cache folders can be removed while the app is closed. Video output folders are separate and should be retained.
